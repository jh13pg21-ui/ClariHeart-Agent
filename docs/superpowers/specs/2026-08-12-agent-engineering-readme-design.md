# ClariHeart Agent 求职展示 README 设计

## 目标

面向 `Agent 开发工程师` 岗位重构 README 的阅读路径，让 HR 在约 30 秒内理解项目定位，让技术面试官能够继续沿代码链接核验 Multi-Agent、Prompt/Context、长期记忆、RAG、模型可靠性与安全治理实现。

## 范围

- 仅修改根目录 `README.md`，不修改业务代码、技术类名、模型名、数据库名或环境变量前缀。
- 保留现有完整技术文档、部署说明、测试命令与项目边界。
- 不虚构用户量、准确率、性能、线上规模或临床效果。

## 信息架构

1. 首屏使用项目名、Agent 工程定位、一句话价值说明和技术标签建立第一印象。
2. 增加短导航，允许读者直接跳转到工程亮点、架构、快速启动、测试和项目边界。
3. 用“30 秒项目速览”表格替代缺乏证据入口的能力罗列。每项同时给出工程问题、实现方式和可点击的代码证据。
4. 在首屏附近展示可复现验证结果：Python `351 passed, 7 skipped`，前端 `9 passed`，并保留完整测试命令。
5. 继续使用现有系统架构图与详细章节承接技术面试官的深入阅读。
6. 将“面试讲述建议”改为更适合开源项目的“关键工程问题”，避免 README 显得只服务于求职。

## 内容原则

- 重点突出 Agent 编排、上下文工程、长期记忆、模型网关和安全边界，而不是泛化描述“调用大模型”。
- 所有能力描述必须能链接到仓库中的实现目录、核心文件或测试目录。
- 徽章只表达可验证的技术栈、许可证或自动化状态；无许可证时不展示许可证徽章。
- 使用中文为主，保留必要的英文技术术语，避免堆叠营销词。

## 验证标准

- README 首屏包含 `ClariHeart Agent`，不再出现旧展示名称。
- 技术标识 `MindBridgeAgentHarness` 等保持不变。
- 所有新增相对链接指向实际存在的文件或目录。
- Markdown 无冲突标记、尾随空格或坏链接目标。
- 完整 Python 与前端测试继续通过。
